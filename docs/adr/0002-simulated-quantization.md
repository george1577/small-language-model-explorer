# Simulated NF4/int8 quantization instead of bitsandbytes

The example script quantizes with bitsandbytes (`BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4")`), which needs an NVIDIA GPU and doesn't run on a Mac. The Quantization tab instead does the same arithmetic in plain PyTorch (`slm_lab/quantization.py`): blocks of 64 weights, one absmax scale per block, snap to the nearest of the 16 NF4 levels (or 255 int8 levels), then de-quantize back to ordinary floats and run the model. This reproduces the accuracy effect of quantization exactly and lets the app show every step on a real block of weights, but it gives no real memory or speed saving at run time, so memory figures are calculated rather than measured and the tab says so. The int8 scheme is a simplification of bitsandbytes' LLM.int8() (no outlier handling). The weights are swapped in place and restored afterwards to avoid holding a second copy of the model in 8 GB of RAM.
