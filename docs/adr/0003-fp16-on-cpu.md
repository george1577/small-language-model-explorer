# Both models run in fp16 on the CPU

The example scripts load models in bfloat16, and the plan was to do the same so both models fit on an 8 GB laptop. Measured on an Apple M2 (macOS 14, PyTorch CPU): Qwen2.5-1.5B in bf16 took about 7 seconds per token, in fp16 about 0.07 seconds per token, and Apple's MPS GPU backend hung. We first kept the small model in fp32 (2 GB) next to the large one in fp16 (3 GB), but speculative decoding then ran 15× *slower* than the target model alone: it alternates between the two models every round, and with 5 GB of weights on a busy 8 GB Mac the operating system kept swapping one model out to load the other. With both in fp16 (about 4 GB together) speculative decoding ran 1.7× faster in the same test. The cost is that fp16 is slow at reading long prompts on a CPU (a few seconds per hundred tokens for the 1.5B model), so the comparison prompt was shortened and the perplexity test uses 128 tokens per snippet. `SLM_DEVICE=cuda` or `mps` overrides the device; dtypes are set in `slm_lab/lm.py`.
